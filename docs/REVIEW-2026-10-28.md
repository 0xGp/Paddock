# SplitSense: judge's review, debate and re-plan (Oct 28, 2026)

I reviewed the plan the way a sponsor judge would, then tested the claims that could be tested from here: real keys, real Mainnet, real SDK typings and runnable code. Anything marked **verified** was run on Oct 28. Anything marked **inferred** comes from reading the docs or the SDK source.

## 1. Verdict

The design is strong and unusually well-reasoned for a hackathon. The problem is that **none of it was built**. On Oct 28 the repo had no code, while the plan expected the engine, memory layer and a Mainnet restore round-trip by Oct 27. Testing also found two integration assumptions that no longer hold:

1. **Tatum's Sui JSON-RPC is gone.** Settlement confirmation was built on it.
2. **MemWal SDK 0.1.8 has no `listMemories` and doesn't expose expiry.** The memory-count and expiry plan was built on that.

Both are fixable in a day. If the re-plan in §5 holds, the submission is still competitive. If it slips by more than about 2 days, the video and blog get squeezed, and Presentation (20%) collapses first.

## 3. What's wrong, ranked by damage

### Critical (blocks a hard requirement or the demo)
1. **Schedule.** Eight days behind with 13 days left. The fix is ADR-0010 (lean MVP) and §5 below.
2. **Tatum JSON-RPC 404.** Settlement confirmation (`sui_getTransactionBlock`) and incoming-transfer polling (`suix_queryTransactionBlocks`) would have failed on demo day. Move to GraphQL (ADR-0004). Verified.
3. **Restore verification can never pass as specified.** `inputsHash` includes `now`, the last `pattern_snapshot` is older than the ledger, and the newest expenses may not be checkpointed yet. Use separate ledger and learned-state hashes (ADR-0006).
4. **Settlement is the biggest unknown and is scheduled last.** Enoki keys don't exist yet. Gasless `send_funds` may need an address balance rather than coin objects, and Enoki may not execute through our client. Run a 0.01 USDC `settle:smoke` as soon as the keys exist (ADR-0008).

### High (costs points with judges)
5. **There's no way to count memories or see their expiry.** SDK 0.1.8 has no `listMemories`, and no `expires_at` or `end_epoch` anywhere in its types. Use `listNamespaces()` for counts (verified). For expiry, the plan is to read the Walrus `Blob` objects owned by `0x0f4c…b987` (the `owner` returned by `rememberAndWait`) through **Tatum GraphQL** (`address.objects` → `storage.end_epoch`). **Not verified yet:** the query hit a local DNS outage on Oct 28, and the blobs may be owned by the relayer's wallet rather than this address. Test it first on Oct 30. If it works, it also gives the "verify on-chain through Tatum" feature for free.
6. **`restore()` can't guarantee a full restore.** Per the SDK docs it inspects 10 blobs by default, has no pagination, and has a per-owner cap shared across namespaces. Call it in a loop with `limit` until `restored == 0 && !truncated`, keep each namespace under ~50 memories, and show `restored/skipped/total` honestly.
7. **Bulk writes would trip the rate limit.** `rememberBulk` with 20 items could cost 100 points against a 30 points/min key limit. Use batches of 5 or fewer and a budget table (ADR-0007).
8. **Exact `seq` lookups through semantic recall are unreliable.** An exact header query matched our own memory at distance 0.24, not 0, so `seq=7` vs `seq=17` won't separate cleanly. With fewer than 100 memories per namespace, recall broadly with `limit: 100` and filter by the parsed header in code.
9. **The demo debts are too big to settle in the video.** Emeka owes Godspower ₦40,000, which is 26.67 USDC at the group rate. The video settles about 2 USDC, which needs partial settlement, and the spec never defines partial settlement or rounding (ADR-0008).
10. **Judges could exhaust the shared budgets.** Tatum allows 3 requests/second and the relayer 30 points/min per key, shared between `/demo` judges, `/status`, balance chips and live writes. Cache aggressively, keep `/demo` read-only from fixtures (ADR-0009), and consider a second delegate key for reads.

### Medium (spec ambiguity that will cause bugs)
11. The payload `hash` is computed over a payload that contains `hash`. Hash the payload without it (ADR-0006).
12. R10 brings a suppressed suggestion back "if the underlying stats change by more than 20%", but never says which stat. Define it as the share (R3) or confidence (R2) of the subject insight.
13. R2's "or same day-of-month ±3" monthly alternative never fires, because consecutive monthly entries always have gaps of 26–34 days. Drop it or define it properly.
14. `seq` scope is unstated. Make it per `(namespace, kind)` (ADR-0006).
15. `canonicalJSON` must be one implementation, shared between the engine (hashing) and memory (envelope). Use the `canonicalize` package everywhere.

### Low
16. `SETUP_CHECKLIST` has a broken smoke test, and `.env.example` listed `TATUM_SUI_RPC_URL`. Both fixed.
17. Impeccable read `docs/DESIGN.md` (the build plan) as the visual design system. Renamed to `docs/SPEC.md` (ADR-0001).
18. Delete `splitsense-cursor-pack/.env` once `.env.local` is confirmed, so secrets don't exist in two places.

## 4. Debate

**"This is just Splitwise. It's literally the brief's first example."**
- *Prosecution:* Creativity is 20%, and the brief's FAQ says don't copy the brief. Several entries will look the same.
- *Defence:* The brief also says "execution beats novelty". No other entry will have deterministic "Why?" receipts, a verified-restore badge, and Lagos-specific money (diesel, NEPA, data) at once.
- *Verdict:* Defence, but only if the first 15 seconds of the video and the README lead with "can prove every suggestion" and show a "Why?" receipt, not a balance list. Creativity stays about 6.5–7, not higher.

**"Postgres-first means Walrus is just a backup."**
- *Prosecution:* Judges for Best Memory want memory that drives behaviour.
- *Defence:* The learned layer is *read* from Walrus on every session (ADR-0005), and the memory-off toggle proves the difference.
- *Verdict:* Defence, provided the "from memory · N memories · 410 ms" chip and the toggle are in the first minute of the video.

**"Cut R11 outcome learning when Best Memory asks for the deepest learning loop?"**
- *Prosecution:* R11 is the most memory-native rule in the spec.
- *Defence:* Without nudges (R9 is cut) R11 has nothing to learn from. R10 dismissal learning plus the R1 alias correction already show the app learning from what users do, and both are cheap.
- *Verdict:* Cut it now. Bring back only R11's rotation half ("accepted rotations that weren't followed raise the bar") after M4, since it needs no nudges.

**"Gasless zkLogin USDC in 13 days is too risky. Use a normal wallet."**
- *Prosecution:* Enoki isn't set up, and two behaviours are unverified.
- *Defence:* Invisible crypto is half the consumer pitch, and Tatum `executeTransaction` exists.
- *Verdict:* Timebox it. If `settle:smoke` doesn't pass by Nov 2, fall back to Slush plus self-paid gas and say so honestly. The memory and Tatum scores don't depend on gasless.
